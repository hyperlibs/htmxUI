Introduction

HTMX on Steroids. Hyper Reactive. Lean. Built for Humans and AI Agents.

What is HTMXUI?

HTMXUI is not a component library bolted on top of htmx. It is a deliberate fork and reinvention of htmx into a hyperreactive, lean, hypermedia-first framework.

Original htmx completed HTML as a hypermedia. HTMXUI completes it as a reactive, agent-friendly, composable application platform — while remaining radically lean.

HTMXUI = HTMX (Hypermedia Engine) + Shadcn-quality Components (100+) + Bolt (Reactive Engine ~2KB) + Flash (In-Memory Search Engine) + Canvas (Visual Node Editor)

The Core Stack

htmx-bolt.js

~2KB

Signal-inspired proxy-based reactive layer. Declare local state with hx-state, bind with hx-text, hx-show, hx-class, hx-style, trigger actions with hx-action. Server can push state updates via HX-Trigger header. The missing middle ground between pure htmx round-trips and full SPA frameworks.

htmx-flash.js

Search Engine

Zero-latency in-memory search engine. Loads data once, pre-processes searchable fields, filters thousands of items in 0ms. Perfect for command palettes, filterable tables, instant search.

htmx-canvas.js

Spatial Engine

Vanilla JS spatial engine for node editors. Supports draggable nodes (hx-drag), grid auto-snapping (hx-snap), 2-layer nesting, and dynamic Bézier curve elastic connectors (hx-connect).

100+ Components

Shadcn Quality

Shadcn/ui-quality components. Copy-paste HTML. No NPM, no Virtual DOM, no build step for logic.

Benefits for Human Developers

  1. Zero NPM, zero Virtual DOM — no node_modules, no React, no webpack
  2. Server remains the source of truth — true hypermedia architecture
  3. Copy-paste components — full ownership, no black-box abstractions
  4. Instant local reactivity via Bolt — dropdowns, tabs, toggles feel native without round-trips
  5. Backend agnostic — works with Python, Go, PHP, Rust, Bun, any language that returns HTML
  6. Tailwind-native theming — CSS variable system for dark mode, custom brands
  7. Sub-3KB total client JS for reactivity + search — smaller than a single React hook
  8. Progressive enhancement — start with pure htmx, add Bolt/Flash only where needed
  9. Layout primitives for real apps — dashboard scaffolds, marketing pages, print layouts, visual canvases
  10. No build step for logic — HTML is the component, the server is the framework

Benefits for Agentic AI Coders

  1. Highly regular HTML structure — AI agents can parse, generate, and modify UI with high success rates
  2. Declarative attribute-based behavior — no imperative JS to reason about
  3. Predictable composition — slots, regions, and contracts that agents can reliably assemble
  4. Minimal hidden side effects — what you see in the HTML is what happens
  5. Machine-readable component patterns — consistent naming, consistent attributes across 100+ components
  6. No complex build toolchain to break — agents don't need to manage webpack/vite/turbopack configs
  7. Server-driven mutations — agents can modify UI by returning HTML fragments, not by managing client state graphs
  8. Copy-paste atomic components — agents can compose UIs by concatenating well-defined HTML blocks
  9. Stable, documented contracts — hx-state, hx-action, hx-text, hx-show form a small, learnable grammar
  10. Lower error surface than React/Vue — no JSX transpilation, no hook ordering rules, no hydration mismatches

Design Pillars

Pillar Meaning Non-Goal
Hyperreactive Fine-grained, efficient reactivity that works with server-driven HTML Becoming a full SPA framework
Lean Minimal runtime, minimal concepts, maximal clarity Feature bloat or "everything included"
Hypermedia-first Server remains the source of truth; HTML is the primary medium Client-side state ownership by default
Agentic-native Structure and semantics that AI agents can reliably generate & reason about Human-only ergonomics
Composable Clear contracts for assembling UI, behavior, and layouts Opaque magic or highly coupled systems
